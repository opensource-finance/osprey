# AGENTS.md

This file gives instructions to coding agents that work in this repository.
Read it before you change code or docs.
[CONTRIBUTING.md](CONTRIBUTING.md) and [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) give more detail.

## Project

Osprey is a real-time transaction monitoring engine for anti-money laundering (AML).
It is one Go binary with an HTTP API.
Rules are CEL expressions. Typologies group the rules for compliance mode.

| Path | Contents |
|---|---|
| `cmd/osprey` | The server entry point. `main.go` reads the `OSPREY_*` environment variables. |
| `cmd/benchmark` | The benchmark tool |
| `internal/api` | The chi router, the handlers, and the middleware |
| `internal/rules` | The CEL rule engine, the typology engine, and the CEL variable catalog |
| `internal/tadp` | The decision processor (ALRT or NALT) |
| `internal/velocity` | The velocity aggregates |
| `internal/worker` | The async workers |
| `internal/repository` | The SQLite and PostgreSQL storage, the schema, and the migrations |
| `internal/cache`, `internal/bus` | The memory or Redis cache, and the channel or NATS bus |
| `internal/domain` | The shared types and interfaces |
| `configs/rules`, `configs/typologies` | The FATF and PaySim starter content in JSON |
| `docs/api/openapi.yaml` | The API contract |
| `tests/integration`, `scripts` | The integration suite and the shell gates |

## Setup

- Use Go 1.26 or later. The module targets `go 1.26`.
- To install `golangci-lint` and `deadcode`, run `make tools`.
- To activate the commit-msg hook, run `make hooks`.
- To start the server, set `OSPREY_ADMIN_TOKEN`. Then run `make run`.

## Checks

GitHub does not run CI on pull requests. The only workflow is `release.yml`.
You must run the gates on your computer.

| Command | When to run it |
|---|---|
| `make test` | After each change. It runs `go test -short ./...`. |
| `make ci` | Before each commit. It runs the `go fix` drift check, vet, lint, race tests, build, and the `gofmt` check. |
| `make lint-complexity` | It is part of `make lint`. A new or changed function must have a gocognit score of 30 or less. |
| `make coverage-check` | If you remove tests or code. Coverage must stay within 0.5 points of `coverage-baseline.txt`. |
| `make test-integration` | If you change the API, the worker, or the storage. It starts a server on port 18080. |
| `make docs-lint` | If you change a Markdown file or `docs/api/openapi.yaml` |
| `make check-vuln` | If you change `go.mod`. It needs network access. |

## Code rules

- Write tests for new behavior. Put a regression test next to each bug fix.
- If you change detection content, read [docs/RULE_TYPOLOGY_AUTHORING.md](docs/RULE_TYPOLOGY_AUTHORING.md).
- Use `has()` guards for optional fields in CEL rules.
- Keep the SQLite and PostgreSQL paths equal. Each schema change must work on the two drivers.
- If the API changes, update `docs/api/openapi.yaml` in the same pull request.
- If a change has an effect on users, update `CHANGELOG.md` under `## [Unreleased]`.
- Do not edit `scripts/lint-message.sh`. It is a copy from `josephgoksu/standards`.

## Docs rules

All docs use ASD-STE100 Simplified Technical English.
[docs/STYLE.md](docs/STYLE.md) gives the rules and the approved words.

- Write 25 words or fewer in each sentence.
- Do not use semicolons or em dashes.
- Write instructions as commands.

## Commits and pull requests

`scripts/lint-message.sh` checks the commit messages and the pull request text.
The rules are:

- Do not add a `Co-Authored-By` trailer.
- Do not name an AI tool or an assistant. Do not write "generated with" or "generated by".
- Do not use em dashes.
- Do not use the filler words that the script lists.
- Write the pull request title as a conventional commit: `<type>(<scope>): <summary>`. Use 72 characters or fewer.

Maintainers merge with squash only.
GitHub makes the commit on `main` from the pull request title and body.
Use the template in `.github/PULL_REQUEST_TEMPLATE.md` for each pull request.
Keep each pull request on one topic.

## Safety

- **WARNING:** Do not commit a token, a password, or a `.env` file. The repository is public.
- **WARNING:** Do not report a security problem in a public issue. Follow [SECURITY.md](SECURITY.md).
